# awflex

A small ansible runner for Kubernetes, for one job: nodes of a large cluster
call in when they boot and get a playbook run on them.

One Go binary in one pod. No database, no Redis, no UI, no operator, no pod per job.
Agents and people drive it through REST or the CLI; both speak JSON.

**Deploying or fixing it? Read [AGENTS.md](AGENTS.md) and run `awflex doctor`.**

```
node boots ──POST /api/v1/hook?host=me&branch=X──▶ awflex ──ssh──▶ ansible-playbook on that node
agent      ──awflex run / get / log / status─────▶   │
                                                     └─ /data: queue + last run per host
```

## How it works

1. **A call is accepted and written to disk.** The hook returns `202` at once. The
   host's record (`/data/runs/<host>.json`) is written as `queued` and fsynced
   before the reply.
2. **Callers share ansible runs.** Calls for the same branch and playbook are
   collected for a fixed 10 seconds from the first caller, then run as one `ansible-playbook`
   process over all of them (up to 100 hosts; a full batch starts early). 1000
   nodes booting together cost about ten ansible runs, not a thousand.
3. **A fork budget caps memory.** `AWFLEX_MAX_FORKS` is the total number of
   ansible forks across all running batches. When it is used up, new callers
   keep collecting and start when a run ends.
4. **Each host gets its own result.** A callback plugin (embedded in the binary)
   records every task result per host, so a host in a 100-host batch still has
   its own status, failed task, and log.
5. **Only the last run per host is kept.** A new run on a host replaces its
   record and log. Raw ansible output is deleted once no host's last run points
   at it.

### Who may ask for what

| Caller | May set |
|---|---|
| A node, through the hook | Its host name, the branch and the playbook. Variables only with `AWFLEX_HOOK_EXTRA_VARS=1`. Never tags or check mode. |
| An API caller with the admin token | Everything: hosts, branch, playbook, variables, tags, skip tags, check mode. |

A node is the least trusted caller, so anything it may not set is refused with
`400` instead of being dropped silently. Set `AWFLEX_HOOK_TOKEN` so that only
your nodes can call the hook at all.

### Restart and crash behavior

The host record is the queue and the finish marker. It moves `queued` →
`running` → a final status, and the final status is written only when ansible
reports its summary for that host.

| What happens | Result |
|---|---|
| awflex or its node dies | On start, every record still `queued` or `running` is re-queued and run again. |
| Pod is deleted or rolled (SIGTERM) | Running ansible is stopped, unfinished hosts go back to `queued` on disk, the next pod resumes them. The attempt is not counted. |
| ansible is killed mid-run (for example out of memory) | Hosts without a finish are re-queued automatically. |
| A request keeps killing ansible or the pod | After `AWFLEX_MAX_ATTEMPTS` (3) starts it becomes `error`, so one bad request cannot loop forever. |

Playbooks must be safe to run twice, since a host interrupted mid-run starts over.
Run one replica: the volume has a single writer.

### Statuses

`queued`, `running`, then one of `successful`, `failed` (a task failed),
`unreachable` (ssh could not reach the host), `error` (awflex, git or ansible
could not run the play: unknown branch, missing playbook, host not in the
inventory), `canceled`, `timeout`.

## Inventory

Real playbooks usually depend on a host's groups, because that is where its
variables come from. There are two modes.

- **Configured inventory (recommended).** Set `AWFLEX_INVENTORY` to one or more
  comma separated inventories. Each is a path inside the playbook repo, or an
  absolute path to a file or directory mounted into the pod (for an inventory
  generated by another system). Runs use `--limit` on the calling hosts, so each
  host has its real groups. A caller naming a host that is not in the inventory
  gets nothing run: ansible ignores it and awflex records the host as `error`.
- **Generated inventory.** With `AWFLEX_INVENTORY` unset, awflex builds an
  inventory from the calling hosts, in a group named `awflex` plus any groups in
  `AWFLEX_GROUPS`. This suits simple playbooks and testing. Every name a caller
  gives is accepted and connected to.

### Dynamic inventory, cached

An inventory plugin that queries another system (a CMDB, a cloud API) works as
a configured inventory: put its config file in the repo, name it in
`AWFLEX_INVENTORY`, and install its collection in the image. Without a cache,
every ansible run queries that system.

Set `AWFLEX_INVENTORY_CACHE` (for example `10m`) to query it far less:

- awflex runs `ansible-inventory --list --export` over `AWFLEX_INVENTORY` from
  the `AWFLEX_BRANCH` checkout and saves the result on the data volume. Runs
  read the saved file. Group vars stay on groups and host vars on hosts,
  including `group_vars` next to the inventory and vault-encrypted values, which
  stay encrypted.
- The cache is refreshed when it is older than the setting, when a caller's host
  is not in it (so a node added to the source is found on its first call; at
  most once every 30 seconds), on start when it is stale, and on demand with
  `awflex inventory refresh`.
- A failed refresh keeps the last good cache and is shown in
  `awflex inventory`, `awflex status` and `awflex doctor`, with the fix.
- A credential's `inventory_env` reaches only the refresh, never a playbook, so
  the plugin's token stays out of every run:
  `awflex cred set inventory --inventory-env-file API_TOKEN=/path/to/token`
  (the variable name is whatever the plugin reads).

Several sources can be listed in `AWFLEX_INVENTORY`, for example one plugin
file per site; one source failing is reported as a warning and the others are
still used. Playbook-side `group_vars` and `host_vars` load from the checkout at
run time as usual.

## SSH, jump hosts and credentials

Credential fields: `ssh_user`, `ssh_private_key`, `become_password`,
`vault_password`, `git_user`, `git_token`, `git_ssh_key`, `env`, and
`inventory_env` (only for refreshing a cached inventory). Every stored
credential applies to every run; fields merge in name order. The API returns only
which fields are set. Per run they are written to tmpfs with mode 0600 and removed
when ansible exits. Authentication to nodes is by SSH key; password login is not
supported.

The SSH key is passed to ansible as a key file and is also loaded into an
`ssh-agent` that exists only for that run. The agent is what makes connections
through a jump host work when the hop relies on agent forwarding, for example a
`ProxyCommand` or `ProxyJump` in the inventory's SSH arguments with
`ForwardAgent=yes`. The agent is stopped when the run ends, and the key in it
expires on its own shortly after the run timeout. `AWFLEX_SSH_AGENT=0` turns it
off.

Values a playbook needs from the environment, such as a token for a secrets
service, go in a credential's `env`.

Credentials can be managed through the API (encrypted on the volume when
`AWFLEX_SECRET_KEY` is set) or mounted from a Kubernetes Secret of `<name>.json`
files with `AWFLEX_CREDENTIALS_DIR`.

## Deploy

Docker is not needed. `deploy/deploy.sh` builds the image with Apple's
`container` tool on macOS, or podman or nerdctl on Linux, then tests, pushes and
deploys it:

```sh
cp deploy/deploy.env.example ~/my-site/awflex-deploy.env   # keep it in your own repo; fill it in
make deploy CONFIG=~/my-site/awflex-deploy.env             # or: deploy/deploy.sh --config FILE
```

The steps, in order (run any of them alone, for example `make smoke CONFIG=...`):

| Step | What it does |
|---|---|
| `build` | Cross-compiles awflex on your machine for the cluster's architecture and builds the image on your ansible image (`BASE_IMAGE`). Every build gets a new tag: version, commit and time. |
| `smoke` | Runs the image on your machine as uid 1000 with a read-only root and runs `awflex doctor` in it, so a broken image is caught before it is pushed. Skipped with a warning when this machine cannot run the target architecture. |
| `push` | Pushes the new tag. A login failure names the login command. |
| `secrets` | Creates the token Secret and the image pull Secret if they do not exist. Never replaces one. |
| `apply` | Applies your manifest with the new image and waits for the rollout. If it does not finish, it shows the pod's events and logs and names the fix. |
| `doctor` | Runs `awflex doctor` in the pod, with a real connection to `DOCTOR_HOST`. |

[AGENTS.md](AGENTS.md) lists known symptoms with their fixes.

### Building awflex itself

```sh
make            # bin/awflex for this machine
make dist       # macOS and Linux, arm64 and amd64, with SHA256SUMS, in dist/
make install    # bin/awflex into ~/.local/bin (PREFIX= to change)
make test       # unit tests
```

The macOS binary is the full CLI: point it at the server with `AWFLEX_URL` and
`AWFLEX_TOKEN`, for example through `kubectl port-forward svc/awflex 8080:80`.

The manifest is a Deployment (1 replica, `Recreate`), a ConfigMap, a Service and
a 2Gi volume claim. It names no namespace and creates none. The pod runs as a
non-root user with a read-only root filesystem and no Kubernetes API access.

- **Storage.** Any volume type works for `/data`. Where volume claims are not
  available, use a direct `nfs:` volume; the manifest says which lines to change.
- **Private registry.** Set `PULL_SECRET` and the registry login in the deploy
  config, and the secrets step creates it. By hand, the command is in the
  manifest. Use a new image tag for every build (deploy.sh does), or set
  `imagePullPolicy: Always` for a reused tag.
- **Reaching it from nodes.** Nodes outside the cluster cannot reach a
  ClusterIP. `deploy/k8s/ingress.yaml` is an example Ingress with TLS; set
  `AWFLEX_TRUST_PROXY=1` behind it. NodePort or LoadBalancer also work.
- **Your own ansible image.** If your playbooks need particular collections,
  Python modules or CA certificates, build on the image that already has them: set `BASE_IMAGE` for deploy.sh. By
  hand: `podman build -f deploy/Containerfile.base --build-arg BASE_IMAGE=<image> .`
  (`container build` on macOS takes the same arguments). The base needs `ansible-playbook`, `git`, an OpenSSH client and `/bin/sh`.
  The build adds a passwd entry for uid 1000 when the base has none, because
  ssh refuses to run for a user id it cannot look up. It does not need an init
  binary: as process 1, awflex reaps the ssh processes ansible leaves behind.
- **Sizing.** Idle memory is a few MB. Under load it is ansible's: run your
  playbook on one host, measure memory per fork, then set the pod limit and
  `AWFLEX_MAX_FORKS` together. The numbers in the manifest are a starting point
  for a small playbook, not a recommendation.

### Configuration

There is one playbook repo and one set of run settings, fixed at deploy time.

| Variable | Default | Meaning |
|---|---|---|
| `AWFLEX_REPO` | required | Git URL of the playbook repo. |
| `AWFLEX_BRANCH` | `main` | Branch when a caller names none. |
| `AWFLEX_PLAYBOOK` | `main.yml` | Playbook when a caller names none. |
| `AWFLEX_INVENTORY` | unset | Inventories, repo relative or absolute. See Inventory. |
| `AWFLEX_INVENTORY_CACHE` | unset | Cache `AWFLEX_INVENTORY` for this long, for example `10m`. See Dynamic inventory. |
| `AWFLEX_GROUPS` | unset | Groups for hosts when the inventory is generated. |
| `AWFLEX_EXTRA_VARS` | unset | JSON object applied to every run. |
| `AWFLEX_HOOK_EXTRA_VARS` | unset | `1` lets a node pass variables through the hook. |
| `AWFLEX_BATCH_WINDOW` | `10` | Seconds callers are collected into one ansible run. |
| `AWFLEX_MAX_BATCH` | `100` | Hosts per ansible run. `1` gives one run per host. |
| `AWFLEX_FORKS` | `25` | Forks per ansible run. |
| `AWFLEX_MAX_FORKS` | `50` | Forks across all runs. The memory knob. |
| `AWFLEX_MAX_ATTEMPTS` | `3` | Starts before a never-finishing request is given up. |
| `AWFLEX_TIMEOUT` | `2h` | Limit for one ansible run. |
| `AWFLEX_FETCH_TTL` | `10` | Seconds a git fetch is reused. |
| `AWFLEX_SSH_AGENT` | `1` | Hold the SSH key in a per-run agent. |
| `AWFLEX_ADMIN_TOKEN` | required | Bearer token for everything. |
| `AWFLEX_READ_TOKEN` | unset | Bearer token for read-only routes. |
| `AWFLEX_HOOK_TOKEN` | unset | If set, nodes must send it; otherwise the hook is open. |
| `AWFLEX_SECRET_KEY` | unset | Encrypts API-managed credentials on disk (AES-256-GCM). |
| `AWFLEX_CREDENTIALS_DIR` | unset | Directory of `<name>.json` credentials from a mounted Secret. |
| `AWFLEX_DATA_DIR` | `/data` | Queue, last runs, credentials, git cache. |
| `AWFLEX_TMP_DIR` | `<data>/tmp` | Per-run key files; tmpfs in the manifest. |
| `AWFLEX_LISTEN`, `AWFLEX_TLS_CERT`, `AWFLEX_TLS_KEY`, `AWFLEX_TRUST_PROXY` | `:8080` | Listener, optional TLS, trust `X-Forwarded-For`. |

Any variable also reads from `NAME_FILE`. `ANSIBLE_*` variables set on the pod are
passed to ansible. Playbooks get a minimal environment; awflex's tokens never reach
them. Host key checking is off, because reinstalled nodes change keys.

Runs use ansible's built-in `default` stdout callback, whatever the repo's
`ansible.cfg` says. awflex reads results from its own callback, so the stdout
callback only shapes the raw log, and one the image lacks would stop every run
before its first task. Set `ANSIBLE_STDOUT_CALLBACK` on the pod to choose another.

## When something does not work

`awflex doctor` checks the deployment from inside the server, in the order a run
needs it: the user (ssh needs a passwd entry), writable directories, ansible,
git and ssh tools, credentials, the repo and default branch, the playbook,
callback plugins, the inventory, a syntax check with the image's collections,
and which hosts the play targets. `--host H` also connects to H the way a run
would, through the same inventory, key, agent and `ansible.cfg`. Each failed
check has a `fix`. It exits 3 when a check failed.

```sh
kubectl exec deploy/awflex -- awflex doctor --host node001
```

A run that does not succeed carries a `hint` when its error is a known one: the
likely cause and the exact fix. It is in `awflex get HOST` and in the host's log.


A caller can name a branch, a tag or a commit SHA, so a rollout can be pinned to
one exact revision.

## Nodes: the boot hook

Install `deploy/node/awflex-callback` to `/usr/local/sbin/`, the unit to
`/etc/systemd/system/`, and write `/etc/awflex/callback.env`:

```sh
AWFLEX_URL=https://awflex.example.com
AWFLEX_HOOK_TOKEN=...
AWFLEX_BRANCH=main                      # optional
AWFLEX_PLAYBOOK=main.yml                # optional
AWFLEX_CACERT=/etc/pki/internal-ca.pem  # optional, for a private CA
```

At boot the node sends its `host`, `branch` and `playbook`, and awflex runs that
playbook from that branch on that node only. A kernel parameter overrides the
file, so a boot entry can pin a node to a branch: `awflex.branch=my-fix`
(likewise `awflex.playbook=`).
The call retries for five minutes and is safe to repeat.

By hand: `curl -X POST -H "Authorization: Bearer $TOKEN" "$AWFLEX_URL/api/v1/hook?host=$(hostname -f)&branch=main"`.
Without `host`, awflex uses the reverse DNS name of the caller.

## CLI and API

`awflex help` lists the commands; `GET /api/v1` (or `awflex api`) returns every
route with its auth level and parameters, for agents to read. Set `AWFLEX_URL` and
`AWFLEX_TOKEN`.

```sh
awflex cred set fleet --ssh-user root --ssh-key-file ~/.ssh/fleet --vault-password-file vault.txt
awflex run node001 node002 --branch fix-nfs --wait   # exit 3 unless all succeed
awflex runs --status failed                          # which nodes are broken
awflex get node001 --wait 600                        # block until final
awflex log node001                                   # that host's tasks only
awflex log node001 --raw                             # whole ansible output of its batch
awflex status                                        # queue, batches, fork budget
awflex config                                        # effective server settings
awflex doctor --host node001                         # check the deployment, exit 3 on a failure
awflex inventory --hosts                             # the cached inventory, with host names
awflex inventory refresh                             # query the inventory sources now
```

| Route | Auth | |
|---|---|---|
| `POST /api/v1/hook` | hook | Node callback. `host`, `branch`, `playbook` by query, form or JSON. |
| `POST /api/v1/runs` | admin | `{hosts, branch, playbook, extra_vars, tags, skip_tags, check}` |
| `GET /api/v1/runs[?status=]` | read | Last run of every host. |
| `GET /api/v1/runs/{host}[?wait=N]` | read | Last run of one host. |
| `GET /api/v1/runs/{host}/log[?raw=1]` | read | Text log. |
| `POST /api/v1/runs/{host}/cancel` | admin | Drop a queued host. |
| `DELETE /api/v1/runs/{host}` | admin | Forget a host. |
| `POST /api/v1/batches/{id}/cancel` | admin | Kill a running ansible process. |
| `GET /api/v1/status`, `/api/v1/config` | read | Queue and settings. |
| `GET /api/v1/doctor[?host=H]` | admin | Check the deployment; every failure has a fix. |
| `GET /api/v1/inventory[?hosts=1]` | read | The cached inventory: size, age, last error. |
| `POST /api/v1/inventory/refresh` | admin | Query the inventory sources now. |
| `GET/PUT/DELETE /api/v1/credentials[/{name}]` | read/admin | Secrets are write-only. |
| `GET /healthz`, `/metrics` | none | Liveness, Prometheus (`awflex_hosts{status="failed"}` is the alert). |

A call for a host that is already queued with the same request returns the same
run. A different request replaces the queued one. A call while the host is running
is parked on the record (`next`) and starts when the run ends.

## Measured

Kubernetes numbers are from the pod's cgroup on a local k3s cluster with version
0.1.0, using a trivial playbook over the local connection (no SSH, no fact
gathering), so they show awflex's own overhead and a lower bound for ansible's.

| | |
|---|---|
| Idle pod memory | 4 to 14 MB |
| 301 nodes calling at once, `MAX_FORKS=50` | 21 s, 4 ansible runs, peak 1.2 GB |
| 1000 nodes calling at once (macOS host, 10 s window) | 78 s, all successful |
| Image | 181 MB |
| Pod deleted with 3 hosts mid-run | all 3 resumed and finished in the new pod |

## Tests

```sh
make test       # engine, recovery, hook limits, refs, agent, sealing, doctor; uses a fake ansible
make e2e        # real ansible, 200 simulated nodes; NODES=1000 for more
```

Not exercised by these tests: SSH to real remote nodes, a real jump host, and
git authentication to a private repo. The tests show the run's agent holds the
key and that the arguments reach ssh and git; verify the rest against your own
fleet and git server.

## Limits

- Hosts in one batch move through the playbook together under ansible's default
  `linear` strategy, so a slow host delays its batch. Use `strategy: free` in the
  play, or lower `AWFLEX_MAX_BATCH`.
- A git outage or an unknown branch marks the hosts `error`; nothing retries
  them. `awflex runs --status error` finds them.
- No schedules, RBAC, workflows, surveys or notifications.
- `ANSIBLE_CALLBACKS_ENABLED` from the pod environment is kept, but the same
  setting in the repo's `ansible.cfg` is overridden, and so is the repo's
  `stdout_callback`.

## Changes

**0.6.0** caches a dynamic inventory.

- `AWFLEX_INVENTORY_CACHE` saves the inventory sources' result and refreshes it
  by age, for a caller missing from it, and on demand. A failed refresh keeps the
  last good cache. `awflex inventory [refresh]`, `GET /api/v1/inventory` and
  doctor's `inventory_cache` check show its state.
- Credential field `inventory_env`: environment for the refresh only, never for
  a playbook. `awflex cred set` takes `--inventory-env-file K=FILE` and
  `--env-file K=FILE` so tokens never go on the command line.
- Doctor's connection test now runs beside the configured playbook, so the
  repo's playbook-side `group_vars` (often the connection settings) apply as in
  a run.
- A host's log is written before its record turns final, so `awflex get --wait`
  followed by `awflex log` always shows the matching log.
- deploy.sh: the registry auth file setting is now `REGISTRY_AUTH_FILE`
  (was `DOCKER_CONFIG_JSON`).

**0.5.0** builds and deploys without Docker.

- `deploy/deploy.sh` (and `make deploy`) builds with Apple's `container` on
  macOS or podman or nerdctl on Linux, tests the image locally, pushes it,
  creates missing secrets, applies, waits, diagnoses a failed rollout, and runs
  doctor. Every build gets a new tag. Site settings live in a config file kept
  in the site's own repository (`deploy/deploy.env.example`).
- A `Makefile` cross-compiles awflex for macOS and Linux on arm64 and amd64
  with checksums (`make dist`).
- The build files are now `Containerfile`, `deploy/Containerfile.base` and the
  new `deploy/Containerfile.prebuilt`, which uses a binary built on your machine
  so no Go image has to be pulled. `GO_IMAGE` points the in-image build at a
  mirror.
- `awflex doctor --text` prints one line per check.

**0.4.0** makes a broken deployment say what to fix.

- `awflex doctor [--host H]` (and `GET /api/v1/doctor`) checks the deployment
  step by step and prints the fix for each failure. With a host it makes a real
  connection the way a run does.
- A failed run carries a `hint` with the likely cause and the exact fix for
  known errors: missing passwd entry, missing callback, collection or role,
  host not targeted, key refused, host key checks in a jump host, DNS and
  network, git authentication and URL, CA trust, become and vault passwords,
  out of memory.
- Runs use ansible's `default` stdout callback unless the pod sets
  `ANSIBLE_STDOUT_CALLBACK`, so a repo's `stdout_callback` that the image lacks
  no longer stops every run.
- `deploy/Dockerfile.base` (now `Containerfile.base`) adds a passwd entry for uid 1000 when the base image
  has none, so ssh works without running as root. The server warns at startup
  when its user has no passwd entry.
- Inside the pod the CLI uses the pod's admin token, so `kubectl exec ... awflex`
  works with no setup. Connection and token errors say what to set.
- The manifest shows the pull secret, the NFS swap step by step, and the image
  tag rule. [AGENTS.md](AGENTS.md) is a deploy and troubleshooting guide for
  agents.

**0.3.0** takes back parts of 0.2.0 that did not earn their cost.

- A node may name its playbook again, as in 0.1.0. Variables from a node stay
  refused unless `AWFLEX_HOOK_EXTRA_VARS=1`. The admin API is unrestricted again.
- Removed the inventory pre-check: ansible already ignores hosts that are not in
  the inventory, so the check only ran the inventory twice.
- Removed the branch allowlist, and the settings `AWFLEX_HOOK_ALLOW`,
  `AWFLEX_API_ALLOW`, `AWFLEX_BRANCHES`, `AWFLEX_INVENTORY_CHECK`.
- Back to mirroring the repo's branches and tags, so tags and commit SHAs work
  as a ref on any git server.

**0.2.0**

- The SSH key is held in a per-run agent, for jump hosts.
- Inventories can be mounted files as well as paths in the repo.
- awflex is its own init process; the image no longer needs one.
- `deploy/Dockerfile.base` (now `Containerfile.base`) builds on an existing ansible image.
- The manifest no longer creates a namespace, and shows NFS storage, a mounted
  inventory and an Ingress.
- A node can no longer pass variables or tags through the hook by default.
