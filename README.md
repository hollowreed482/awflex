# awflex

A small ansible runner for Kubernetes, for one job: nodes of a large cluster
call in when they boot and get the configured playbook run on them.

One Go binary in one pod. No database, no Redis, no UI, no operator, no pod per job.
Agents and people drive it through REST or the CLI; both speak JSON.

```
node boots ──POST /api/v1/hook?host=me&branch=X──▶ awflex ──ssh──▶ ansible-playbook on that node
agent      ──awflex run / get / log / status─────▶   │
                                                     └─ /data: queue + last run per host
```

## How it works

1. **A call is accepted and written to disk.** The hook returns `202` at once. The
   host's record (`/data/runs/<host>.json`) is written as `queued` and fsynced
   before the reply.
2. **Callers share ansible runs.** Calls for the same branch are collected for
   a fixed 10 seconds from the first caller, then run as one `ansible-playbook`
   process over all of them (up to 100 hosts; a full batch starts early). 1000
   nodes booting together cost about ten ansible runs, not a thousand.
3. **A fork budget caps memory.** `AWFLEX_MAX_FORKS` is the total number of
   ansible forks across all running batches. When it is used up, new callers
   keep collecting and start when a run ends.
4. **Each host gets its own result.** A callback plugin (embedded in the binary)
   records every task result per host, so a host in a 100-host batch still has
   its own status, failed task, and log.
5. **Only the last run per host is kept.** A new run on a host replaces its
   record and log. Raw ansible output is deleted once no host's last run points
   at it.

### What a caller can and cannot decide

The server's configuration decides what is run. By default a caller chooses
only the **host** and the **branch**; the playbook, variables, tags and check
mode are fixed. A request that tries to set one of those is refused with `400`,
not silently changed, so a caller never believes it ran something it did not.

| Setting | Default | Effect |
|---|---|---|
| `AWFLEX_HOOK_ALLOW` | `branch` | What a node may choose: any of `branch`, `playbook`, `extra_vars`, or `none`. |
| `AWFLEX_API_ALLOW` | `branch` | What an API caller may choose: those, plus `tags`, `skip_tags`, `check`. |
| `AWFLEX_BRANCHES` | any | Patterns of branches a caller may name, for example `main,release/*`. |
| `AWFLEX_INVENTORY` | unset | When set, a host that is not in the inventory is refused before any SSH. |
| `AWFLEX_HOOK_TOKEN` | unset | When set, nodes must send it. |

Keeping the defaults keeps awflex a boot callback. Opening them up turns it
into a general job launcher, which is a different tool with different risks.

### Restart and crash behavior

The host record is the queue and the finish marker. It moves `queued` →
`running` → a final status, and the final status is written only when ansible
reports its summary for that host.

| What happens | Result |
|---|---|
| awflex or its node dies | On start, every record still `queued` or `running` is re-queued and run again. |
| Pod is deleted or rolled (SIGTERM) | Running ansible is stopped, unfinished hosts go back to `queued` on disk, the next pod resumes them. The attempt is not counted. |
| ansible is killed mid-run (for example out of memory) | Hosts without a finish are re-queued automatically. |
| A request keeps killing ansible or the pod | After `AWFLEX_MAX_ATTEMPTS` (3) starts it becomes `error`, so one bad request cannot loop forever. |

Playbooks must be safe to run twice, since a host interrupted mid-run starts over.
Run one replica: the volume has a single writer.

### Statuses

`queued`, `running`, then one of `successful`, `failed` (a task failed),
`unreachable` (ssh could not reach the host), `error` (awflex, git or ansible
could not run the play: unknown branch, missing playbook, host not in the
inventory), `canceled`, `timeout`.

## Inventory

Real playbooks usually depend on a host's groups, because that is where its
variables come from. There are two modes.

- **Configured inventory (recommended).** Set `AWFLEX_INVENTORY` to one or more
  comma separated inventories. Each is a path inside the playbook repo, or an
  absolute path to a file or directory mounted into the pod (for an inventory
  generated by another system). Runs use `--limit` on the calling hosts, so each
  host has its real groups. Before a batch starts, awflex asks
  `ansible-inventory` which hosts exist and refuses the rest. That check is also
  what stops a caller from starting a run against an arbitrary name. Dynamic
  inventory plugins work; the host list is cached for 30 seconds.
  `AWFLEX_INVENTORY_CHECK=0` turns the check off.
- **Generated inventory.** With `AWFLEX_INVENTORY` unset, awflex builds an
  inventory from the calling hosts, in a group named `awflex` plus any groups in
  `AWFLEX_GROUPS`. This suits simple playbooks and testing. Every name a caller
  gives is accepted.

## SSH, jump hosts and credentials

Credential fields: `ssh_user`, `ssh_private_key`, `become_password`,
`vault_password`, `git_user`, `git_token`, `git_ssh_key`, `env`. Every stored
credential applies to every run; fields merge in name order. The API returns only
which fields are set. Per run they are written to tmpfs with mode 0600 and removed
when ansible exits. Authentication to nodes is by SSH key; password login is not
supported.

The SSH key is passed to ansible as a key file and is also loaded into an
`ssh-agent` that exists only for that run. The agent is what makes connections
through a jump host work when the hop relies on agent forwarding, for example a
`ProxyCommand` or `ProxyJump` in the inventory's SSH arguments with
`ForwardAgent=yes`. The key in the agent expires on its own, and the agent is
stopped when the run ends. `AWFLEX_SSH_AGENT=0` turns it off.

Values a playbook needs from the environment, such as a token for a secrets
service, go in a credential's `env`.

Credentials can be managed through the API (encrypted on the volume when
`AWFLEX_SECRET_KEY` is set) or mounted from a Kubernetes Secret of `<name>.json`
files with `AWFLEX_CREDENTIALS_DIR`.

## Deploy

```sh
docker build -t registry.example.com/awflex:0.2.0 . && docker push registry.example.com/awflex:0.2.0

kubectl -n <namespace> create secret generic awflex-auth \
  --from-literal=AWFLEX_ADMIN_TOKEN="$(openssl rand -hex 32)" \
  --from-literal=AWFLEX_HOOK_TOKEN="$(openssl rand -hex 32)" \
  --from-literal=AWFLEX_SECRET_KEY="$(openssl rand -hex 32)"

# set AWFLEX_REPO, AWFLEX_PLAYBOOK, AWFLEX_INVENTORY and the image in deploy/k8s/awflex.yaml, then
kubectl -n <namespace> apply -f deploy/k8s/awflex.yaml
```

The manifest is a Deployment (1 replica, `Recreate`), a ConfigMap, a Service and
a 2Gi volume claim. It names no namespace and creates none. The pod runs as a
non-root user with a read-only root filesystem and no Kubernetes API access.

- **Storage.** Any volume type works for `/data`. Where volume claims are not
  available, use a direct `nfs:` volume; the line is in the manifest.
- **Reaching it from nodes.** Nodes outside the cluster cannot reach a
  ClusterIP. `deploy/k8s/ingress.yaml` is an example Ingress with TLS; set
  `AWFLEX_TRUST_PROXY=1` behind it. NodePort or LoadBalancer also work.
- **Your own ansible image.** If your playbooks need particular collections,
  Python modules or CA certificates, build on the image that already has them:
  `docker build -f deploy/Dockerfile.base --build-arg BASE_IMAGE=<image> .`
  The base needs `ansible-playbook`, `ansible-inventory`, `git` and an OpenSSH
  client. It does not need an init binary: as process 1, awflex reaps the ssh
  processes ansible leaves behind.
- **Sizing.** Idle memory is a few MB. Under load it is ansible's: run your
  playbook on one host, measure memory per fork, then set the pod limit and
  `AWFLEX_MAX_FORKS` together. The numbers in the manifest are a starting point
  for a small playbook, not a recommendation.

### Configuration

There is one playbook repo and one set of run settings, fixed at deploy time.

| Variable | Default | Meaning |
|---|---|---|
| `AWFLEX_REPO` | required | Git URL of the playbook repo. |
| `AWFLEX_BRANCH` | `main` | Branch when a caller names none. |
| `AWFLEX_PLAYBOOK` | `main.yml` | The playbook that is run. |
| `AWFLEX_INVENTORY` | unset | Inventories, repo relative or absolute. See Inventory. |
| `AWFLEX_INVENTORY_CHECK` | `1` | Refuse hosts that are not in the inventory. |
| `AWFLEX_GROUPS` | unset | Groups for hosts when the inventory is generated. |
| `AWFLEX_EXTRA_VARS` | unset | JSON object applied to every run. |
| `AWFLEX_HOOK_ALLOW`, `AWFLEX_API_ALLOW`, `AWFLEX_BRANCHES` | `branch`, `branch`, any | What callers may decide. See above. |
| `AWFLEX_BATCH_WINDOW` | `10` | Seconds callers are collected into one ansible run. |
| `AWFLEX_MAX_BATCH` | `100` | Hosts per ansible run. `1` gives one run per host. |
| `AWFLEX_FORKS` | `25` | Forks per ansible run. |
| `AWFLEX_MAX_FORKS` | `50` | Forks across all runs. The memory knob. |
| `AWFLEX_MAX_ATTEMPTS` | `3` | Starts before a never-finishing request is given up. |
| `AWFLEX_TIMEOUT` | `2h` | Limit for one ansible run. |
| `AWFLEX_FETCH_TTL` | `10` | Seconds the result of a git fetch is reused. |
| `AWFLEX_SSH_AGENT` | `1` | Hold the SSH key in a per-run agent. |
| `AWFLEX_ADMIN_TOKEN` | required | Bearer token for everything. |
| `AWFLEX_READ_TOKEN` | unset | Bearer token for read-only routes. |
| `AWFLEX_HOOK_TOKEN` | unset | If set, nodes must send it; otherwise the hook is open. |
| `AWFLEX_SECRET_KEY` | unset | Encrypts API-managed credentials on disk (AES-256-GCM). |
| `AWFLEX_CREDENTIALS_DIR` | unset | Directory of `<name>.json` credentials from a mounted Secret. |
| `AWFLEX_DATA_DIR` | `/data` | Queue, last runs, credentials, git cache. |
| `AWFLEX_TMP_DIR` | `<data>/tmp` | Per-run key files; tmpfs in the manifest. |
| `AWFLEX_LISTEN`, `AWFLEX_TLS_CERT`, `AWFLEX_TLS_KEY`, `AWFLEX_TRUST_PROXY` | `:8080` | Listener, optional TLS, trust `X-Forwarded-For`. |

Any variable also reads from `NAME_FILE`. `ANSIBLE_*` variables set on the pod are
passed to ansible. Playbooks get a minimal environment; awflex's tokens never reach
them. Host key checking is off, because reinstalled nodes change keys.

Only the branch a caller asks for is fetched, and only its tip commit, so a
large repo with many branches costs no more than the tree that is run. A branch
or tag name always works; a full commit SHA works where the git server permits
fetching by SHA.

## Nodes: the boot hook

Install `deploy/node/awflex-callback` to `/usr/local/sbin/`, the unit to
`/etc/systemd/system/`, and write `/etc/awflex/callback.env`:

```sh
AWFLEX_URL=https://awflex.example.com
AWFLEX_HOOK_TOKEN=...
AWFLEX_BRANCH=main                      # optional
AWFLEX_CACERT=/etc/pki/internal-ca.pem  # optional, for a private CA
```

At boot the node sends its `host` and `branch`, and awflex runs the configured
playbook from that branch on that node only. A kernel parameter overrides the
file, so a boot entry can pin a node to a branch: `awflex.branch=my-fix`.
The call retries for five minutes and is safe to repeat.

By hand: `curl -X POST -H "Authorization: Bearer $TOKEN" "$AWFLEX_URL/api/v1/hook?host=$(hostname -f)&branch=main"`.
Without `host`, awflex uses the reverse DNS name of the caller.

## CLI and API

`awflex help` lists the commands; `GET /api/v1` (or `awflex api`) returns every
route with its auth level and parameters, for agents to read. Set `AWFLEX_URL` and
`AWFLEX_TOKEN`.

```sh
awflex cred set fleet --ssh-user root --ssh-key-file ~/.ssh/fleet --vault-password-file vault.txt
awflex run node001 node002 --branch fix-nfs --wait   # exit 3 unless all succeed
awflex runs --status failed                          # which nodes are broken
awflex get node001 --wait 600                        # block until final
awflex log node001                                   # that host's tasks only
awflex log node001 --raw                             # whole ansible output of its batch
awflex status                                        # queue, batches, fork budget
awflex config                                        # what this server allows callers to decide
```

| Route | Auth | |
|---|---|---|
| `POST /api/v1/hook` | hook | Node callback. `host` and `branch` by query, form or JSON. |
| `POST /api/v1/runs` | admin | `{hosts, branch}` |
| `GET /api/v1/runs[?status=]` | read | Last run of every host. |
| `GET /api/v1/runs/{host}[?wait=N]` | read | Last run of one host. |
| `GET /api/v1/runs/{host}/log[?raw=1]` | read | Text log. |
| `POST /api/v1/runs/{host}/cancel` | admin | Drop a queued host. |
| `DELETE /api/v1/runs/{host}` | admin | Forget a host. |
| `POST /api/v1/batches/{id}/cancel` | admin | Kill a running ansible process. |
| `GET /api/v1/status`, `/api/v1/config` | read | Queue and settings. |
| `GET/PUT/DELETE /api/v1/credentials[/{name}]` | read/admin | Secrets are write-only. |
| `GET /healthz`, `/metrics` | none | Liveness, Prometheus (`awflex_hosts{status="failed"}` is the alert). |

A call for a host that is already queued with the same request returns the same
run. A different request replaces the queued one. A call while the host is running
is parked on the record (`next`) and starts when the run ends.

## Measured

Kubernetes numbers are from the pod's cgroup on a local k3s cluster with version
0.1.0, using a trivial playbook over the local connection (no SSH, no fact
gathering), so they show awflex's own overhead and a lower bound for ansible's.

| | |
|---|---|
| Idle pod memory | 4 to 14 MB |
| 301 nodes calling at once, `MAX_FORKS=50` | 21 s, 4 ansible runs, peak 1.2 GB |
| 1000 nodes calling at once (macOS host, 10 s window) | 78 s, all successful |
| Image | 181 MB |
| Pod deleted with 3 hosts mid-run | all 3 resumed and finished in the new pod |

## Tests

```sh
go test ./...   # engine, recovery, request limits, inventory check, agent, sealing; uses a fake ansible
test/e2e.sh     # real ansible, 200 simulated nodes; NODES=1000 for more
```

Not exercised by these tests: SSH to real remote nodes, a real jump host, and
git authentication to a private repo. The tests show the run's agent holds the
key and that the arguments reach ssh and git; verify the rest against your own
fleet and git server.

## Limits

- Hosts in one batch move through the playbook together under ansible's default
  `linear` strategy, so a slow host delays its batch. Use `strategy: free` in the
  play, or lower `AWFLEX_MAX_BATCH`.
- A git outage or an unknown branch marks the hosts `error`; nothing retries
  them. `awflex runs --status error` finds them.
- No schedules, RBAC, workflows, surveys or notifications.
- `ANSIBLE_CALLBACKS_ENABLED` from the pod environment is kept, but the same
  setting in the repo's `ansible.cfg` is overridden.

## Changes in 0.2.0

- Callers choose only the host and branch by default. In 0.1.0 a node could
  also name the playbook and pass variables; set `AWFLEX_HOOK_ALLOW` and
  `AWFLEX_API_ALLOW` to permit that again.
- Hosts outside the configured inventory are refused; inventories can be
  mounted files as well as paths in the repo; optional branch allowlist.
- The SSH key is held in a per-run agent, for jump hosts.
- Only the requested branch is fetched, at depth 1.
- awflex is its own init process; the image no longer needs one.
- `deploy/Dockerfile.base` builds on an existing ansible image.
- The manifest no longer creates a namespace, and shows NFS storage, a mounted
  inventory and an Ingress.
